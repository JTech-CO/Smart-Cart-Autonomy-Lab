## 수정 후 확인한 다섯 동작

### 화면 기준 입력과 드래그

코어 검사는 카메라 방위 8개, 고도 3개와 직선·대각 입력 8개에서 실제 뷰 행렬에 투영한 방향을 확인했습니다. 브라우저에서는 방위 0°·90°·180°·−90° 각각에서 방향키 네 개를 실제로 누르고, 사람의 화면 투영 이동이 키 방향과 일치하는지 확인했습니다. 단순히 위치가 바뀌었다는 검사에 그치지 않습니다.

실제 마우스로 오른쪽 90 px·위쪽 45 px를 드래그해 방위각·고도가 각각 증가하고 포인터 캡처가 종료되는지 검사했습니다. 드래그 이후 왼쪽 입력, 일시정지 버튼에 초점이 남은 상태의 이동, 입력란의 기본 화살표 동작도 확인했습니다. 모바일은 390×844의 터치 가능 Chromium에서 CDP의 실제 touchStart/touchEnd 이벤트를 방향 버튼에 보내, 카메라를 90° 돌린 상태에서도 왼쪽으로 이동하고 손을 떼면 입력이 해제됨을 확인했습니다. 실제 Android/iOS 단말 시험은 아닙니다.

### 후진과 측면 추종

획득 이력이 있는 태그를 카트 주위로 한 바퀴 이동시켜 양측 PDoA 경계를 넘는 경우를 노이즈 0·1·2에서 검사했습니다. 이 고정 시험에서 위치 최대 오차는 각각 약 0.044 / 0.142 / 0.147 m, 마지막 관측의 최대 나이는 0.040 / 0.040 / 0.100 s였습니다. 이는 **합성 센서 모델의 시험 수치이며 실제 UWB 정확도가 아닙니다.**

좌·우 측면 대상에 대해 각각 약 0.92 / 0.93 m의 저속 재배치와 약 56°의 방향 회복을 확인했고 접촉 수는 0이었습니다. 이후 대상이 측면에서 멀어져도 추정과 이동이 이어졌습니다. 후방의 세 목표 위치에 대해서는 올바른 후진 곡률로 접근한 후 정지했고 접촉은 없었습니다. 실제 브라우저에서 후진 상태, 음수 속도·RPM·PWM 표시를 확인했습니다. 전후진 방향 전환 시 선제동, 관측된 후방 장애물과 지도 경계의 거부도 검사했습니다.

**최초 후방 거리 관측만 있는 상황**은 별도 시험으로, 위치를 만들거나 맹목 후진하지 않음을 확인했습니다. 이력 없이 두 거리만으로 전후 모호성을 해결했다고 주장하지 않습니다. 후방 낮은 물체가 전방 ToF에 보이는 것도 아닙니다.

### 보행자 발과 지형

평지·오르막·내리막·복합 경사 각각 576개, 계단 256개로 총 **2,560개 자세**를 검사했습니다. 사용자와 다른 보행자가 공유하는 실제 발·종아리 메시의 변환된 정점을 지면 높이와 대조했습니다. 선택한 자세에서 최소 여유는 평지·경사 약 6 mm, 계단 약 1.81 mm 이상이었고 허벅지·종아리 길이 오차는 부동소수점 반올림 수준이었습니다. 정지 후 발의 스윙이 멈추는지도 확인했습니다. 브라우저 렌더링에 사용하는 동일한 발 메시가 오르막 지면 위에 있음을 별도로 검사했습니다.

이는 발바닥 지지·두 관절 시각화 검증입니다. 완벽한 발 미끄럼 제거, 발 압력, 전신 생체역학, 모든 지형 메시를 검증한 것은 아닙니다.

### 관성·경사·제동

49 kg의 차체·적재 질량에 회전 관성을 환산하면 유효 질량은 약 53.021 kg입니다. 각 틱의 힘 합과 유효 질량·가속도 관계를 확인했습니다. 같은 명령에도 적재량에 따라 초기 가속 응답이 다르고, 평지에서 오르막으로 들어갈 때 중력 부하가 즉시 상쇄되지 않음을 검사했습니다.

8° 경사에서 구동과 브레이크를 모두 해제한 별도 물리 시험의 1초 후 값은 다음과 같습니다. +/−는 차체 전방/후방 기준입니다.

| 차량 방향 | 속도 | 수평 이동량 | 중력 종방향 힘 |
|---|---:|---:|---:|
| 오르막을 향함 | −1.098 m/s | −0.544 m | −66.899 N |
| 내리막을 향함 | +1.098 m/s | +0.544 m | +66.899 N |

같은 제동 시작 속도의 선택 시험에서는 제동 이동거리가 오르막 0.105 m, 평지 0.164 m, 내리막 0.331 m로 달랐습니다. 모두 현재 가정한 질량·마찰·제동 용량으로 계산한 값이며 실제 카트 성능이 아닙니다. 일반 추종 정지에서는 가정한 주차 브레이크가 요청되므로 경사에서 정지하는 것이 정상입니다. 무제동 자유 구름 시험과 혼동하지 않습니다. RPM·회전 애니메이션·가속도·힘의 부호와 CSV/JSON 확장도 확인했습니다.

## 기존 검사 변경의 공개

기존 적재 오르막 주행 검사의 경과시간을 1,050틱(17.5초)에서 **1,200틱(20초)**으로 변경했습니다. 즉시 중력 상쇄를 없애고 유한 구동 응답을 적용한 결과, 이전 고정 시간에서는 도달 위치가 판정 경계에 못 미쳤기 때문입니다. 지형·적재·도달 위치·유한 값·모터 출력 한계 조건은 유지했습니다. 단순히 시간을 늘린 것만으로 동역학을 검증하지 않고, 새 결함 시험에서 힘 평형·적재 응답·경사 전이·제동 거리·자유 구름을 별도로 검증했습니다.

기존 UI에서는 라이트 테마, 14px 이상 주요 문구, 상태·조작·3D 영역 분리, 펼침형 점군·그래프, ToF mm 단위, 설정 모달, 고장 주입, 초기화, 포커스 이탈과 GPU 자원 해제를 재검사했습니다. CSV·세션 JSON·텔레메트리 JSON·설정 JSON·PNG는 각각 실제 다운로드 이벤트 후 **파일 저장 완료와 바이트**까지 확인했습니다. Blob 생성만 확인한 결과가 아닙니다.

## 렌더링 및 미리보기

Chromium 144.0.7559.96, Linux, ANGLE/SwiftShader 소프트웨어 GPU로 실제 WebGL 2를 실행했습니다. 기본 검사 장면은 87,370개 삼각형·172회 드로 콜, GL 오류 0이었습니다. 320·390·600·820·1024·1366·1600 CSS px 폭에서 가로 넘침과 필수 조작 위치를 검사했습니다. 작은 화면에서 우측 데이터가 문서 아래로 이어지는 것은 의도된 동작입니다. 실제 GPU 성능·일정 FPS·모든 운영체제 글꼴·WCAG 적합성 인증을 주장하지 않습니다.

## 소스 보존과 확인하지 못한 범위

[provenance.json](qa/provenance.json)에 제공받은 원본 ZIP과 각 JS의 SHA-256을 기록했습니다. `math.js`, `world.js`, `gl.js`는 1.1.0과 바이트가 동일합니다. `model.js`의 카트 하드웨어 생성 부분은 동일하며, 사람 부분만 관절 표현을 바꿨습니다. `kinematics.js`·`dynamics.js`는 새 로컬 스크립트이고 외부 의존성이 아닙니다.

이 환경에서 `file://`와 루프백 HTTP 주소를 실제로 탐색했으나 관리형 Chromium이 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단했습니다. 브라우저 검사는 **원본 HTML/CSS/JS 소스를 about:blank 문서에 삽입**하여 실제 DOM 이벤트와 WebGL을 실행했습니다. 별도 임시 루프백 HTTP 서버로 사이트 루트와 저장소 하위 경로에서 HTML·11개 JS·CSS·favicon의 200 응답, 동일 바이트, 올바른 MIME을 확인했습니다. 이 검사는 브라우저 URL 진입부터 완료까지의 E2E 성공이 아닙니다. 정책을 우회하거나 해제하지 않았습니다.

원격 저장소 커밋·푸시·GitHub Actions 실행·실제 Pages 배포는 하지 않았습니다. Safari·Firefox·실제 Android/iOS GPU·물리 센서·모터·브레이크·실시간 Flutter 전송도 검증하지 않았습니다. 알려진 지형 지도, 이상적 오도메트리, 센서 오차·태그 높이·브레이크·모터 계수의 미교정 가정과 후방 광학 사각지대는 [모델 명세](MODEL-KR.md)에 명시했습니다.
