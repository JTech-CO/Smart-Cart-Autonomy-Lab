## 동작 화면 높이

같은 Chromium·시스템 글꼴·창 크기·기기 배율 1에서 제공된 1.1.1 HTML/CSS와 새 앱의 실제 레이아웃을 측정했습니다. 이미지에서 추정한 값이 아닙니다.

| 창 크기(CSS px) | 1.1.1의 3D 높이 | 1.2.0의 3D 높이 | 확보한 높이 |
|---|---:|---:|---:|
| 1600×1000 | 575 px | 691.70 px | 116.70 px |
| 1366×768 | 343 px | 459.70 px | 116.70 px |

기존 하단 주행 요약 75px는 상단 내부의 29px 요약으로 바뀌었습니다. 두 열 계측 패널의 그래프 너비를 확보하기 위해 1600px 창에서 3D 너비는 1208px에서 1056px로 줄고 높이가 늘어납니다. 1200px 이하에서는 데이터 영역이 전체 폭의 3D 아래로 이동합니다. 수치·그래프는 521px까지 나란히, 520px 이하에서는 수치 다음에 그래프가 이어집니다. 320·390·520·521·600·820·1200·1201·1280·1366·1440·1600·1920px에서 수평 페이지 넘침과 숨겨진 시간 그래프가 없는지 확인했습니다.

검사 중 스크린리더용 표 설명이 스크롤 밖 절대 위치로 계산되어 루트가 6px 넘치는 문제도 발견했습니다. 해당 표에 위치 기준을 지정해 설명을 데이터 스크롤 내부에 유지했습니다. 접근성 설명을 삭제하지 않고 해결했습니다.

## 입력과 보행

입력 함수는 카메라를 읽지 않는 고정축 변환만 호출합니다. 코어는 직선·대각선의 방향과 속도 정규화를 검사합니다. 브라우저에서는 실제 키보드·포인터 이벤트로 W·S·A·D를 각각 누른 채 마우스 회전, C 시점 복귀, 상부 시점 변경을 수행했습니다. 이동하지 말아야 할 축의 변위가 허용 오차 이내인지 확인했습니다. 방향키와 실제 터치 이벤트도 고정 지형 좌표 기준으로 재검사했습니다.

1.1.1의 화면 기준 이동 검사는 이번 명시적 요청과 반대이므로 고정 지형 기준 검사로 변경했습니다. 초반 브라우저 검사 한 건은 소프트웨어 GPU 초기 렌더링으로 벽시계 입력 구간 동안 5틱만 진행되어 최소 거리 조건에 실패했습니다. 입력·방향·거리 기준을 완화하지 않고 **모의 시간 0.35초가 진행될 때까지 기다리는 방식**으로 시험 시간을 수정했습니다. 이는 성능 보장이 아니라 검사 타이밍 수정입니다.

발의 유각기는 앞으로, 입각기는 뒤로 단조 이동하며 발 들기는 유각기에만 있습니다. 실제 이동 거리와 보행 위상의 관계로, 일정한 평지 직선 보행에서 지지 발목이 지면에 고정되는지 4개 방향·5개 속도·양발로 검사했습니다. 팔의 반대 흔들림과 실제 이동을 향하는 자세도 확인했습니다. 자율 보행자의 위상·속도·yaw는 충돌 처리 후 변위로 계산해 막힌 상태에서 의도한 속도로 발만 움직이지 않습니다. 기존 2,560개 발·종아리 메시 자세의 경사·전이·계단 지면 침투 검사도 다시 통과했습니다. 급회전·정지 전환·임의 지형의 완전한 접촉 잠금이나 전신 생체역학은 아닙니다.

## 그래프·기존 기능

5개 그래프는 닫힌 펼침 요소 안에 들어가지 않습니다. 각 수치·그래프는 공통 행과 스크롤을 사용합니다. 모두 실제 이력 진행에 따라 다시 그려지는지, 단위가 맞는지, 창 크기 변경과 아래쪽 구동 항목 스크롤 후에도 나란히 배치되는지 검사했습니다. ToF 반환 없음은 여전히 -- 또는 선의 공백이며 0으로 위조하지 않습니다.

CSV·세션 JSON·텔레메트리 JSON·설정 JSON·PNG는 실제 브라우저 다운로드 파일을 저장하고 내용을 확인했습니다. 초기화·GPU 자원 해제·설정 불러오기·모달·포커스·고장 주입·비상정지·후진·측면 추종·계단 정지·경사 힘도 회귀검사했습니다. 미리보기는 계산된 텔레메트리를 표시한 실제 WebGL 화면을 일시정지해 캡처했습니다. 후진·경사 미리보기는 명시한 시험 배치이며 실차 관측 자료가 아닙니다.

## 검증 한계·출처

file://와 루프백 HTTP 진입을 실제로 시도했지만 이 환경의 브라우저가 ERR_BLOCKED_BY_ADMINISTRATOR로 차단했습니다. 따라서 UI·WebGL 검사는 about:blank에 변경하지 않은 로컬 소스 내용을 삽입해 실행했습니다. 별도 루프백 HTTP 검사에서 두 배포 경로의 200 응답·동일 파일 바이트·MIME을 확인했습니다. **URL 진입부터 이어지는 일반 브라우저 E2E와 실제 GitHub Pages 배포 성공을 확인한 것은 아닙니다.** 관리자 정책을 변경하지 않았습니다. [진입 시도 기록](qa/navigation-results.json)

Linux Chromium·ANGLE/SwiftShader·Xvfb에서 실제 WebGL 2를 실행했습니다. Safari·Firefox·실물 모바일·하드웨어 GPU 성능·스크린리더 종단 검사·실차 시험은 하지 않았습니다. 원격 커밋·푸시·Actions 실행도 없습니다. 물리 모델은 미교정 가정입니다. [소스 해시와 변경 범위](qa/provenance.json)

`dynamics.js`, `sensors.js`, `navigation.js`, `simulation.js`, `gl.js`, `model.js`는 제공된 1.1.1과 바이트 단위로 동일합니다. 앱·레이아웃, 순수 입력 변환, 보행자의 실제 변위·보행 위상, 더 이상 쓰지 않는 View 입력 함수 제거, 테스트·문서·패키징을 수정했습니다.

브라우저 검사는 Playwright·Chromium이 필요하며 Linux에서 필요한 경우 Xvfb를 실행하고 DISPLAY=:99를 지정합니다. URL 진입이 허용되는 호스트에서는 SC_TEST_URL을 지정합니다. 높이 비교까지 실행하려면 SC_BASELINE_DIR을 압축 해제한 1.1.1 폴더로 지정합니다. 이 선택 자료가 없으면 신규 브라우저 검사는 45개가 아닌 43개입니다. 시험 도구는 앱 실행 의존성이 아닙니다.
